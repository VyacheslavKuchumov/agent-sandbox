# Agent Sandbox Desktop

Electron-панель для существующей песочницы. Запускается **на хосте**, где доступны
Docker Compose, репозиторий и графический терминал. Linux — платформа первой
версии; WSL требует рабочей графической среды и Linux-терминала.

```sh
cd ~/agent-sandbox/desktop
npm ci
npm run demo        # интерфейс без Docker и системных изменений
npm start           # управление настоящей песочницей
```

После установки зависимостей панель также доступна из корня репозитория:
`bin/sandbox gui` или `bin/sandbox gui --demo`.

Если песочница находится в другом каталоге:

```sh
AGENT_SANDBOX_ROOT=/absolute/path/to/agent-sandbox npm start
```

Панель показывает семь агентов, инфраструктуру, health и названия настроенных
ключей. Список ключей проверяется по метаданным файлов: значения не читаются
и не передаются в интерфейс. Статусы обновляются каждые 10 секунд.

Запуск, остановка и перезапуск контейнеров, проверки и открытие терминала
требуют подтверждения в системном диалоге. `start` агента вызывает
`bin/sandbox up <agent>`: первый запуск может собирать образы и готовить секреты,
как обычная CLI-команда. Перезапуск/остановка выполняются через Docker Compose.
Web — одноразовый агент; его сессия запускается через терминал, а управление
постоянным контейнером для него не предлагается.

CLI открывается в Konsole, GNOME Terminal, XFCE Terminal, xterm или системном
`x-terminal-emulator`. Сообщение об открытии означает отправку запроса терминалу;
успешную авторизацию/работу CLI следует проверить в открывшемся окне.

Логи ограничены последними 150 строками и 256 КиБ вывода. Типовые токены
редактируются, но произвольный секрет, записанный сторонней программой в лог,
может остаться видимым. Не публикуйте логи без просмотра. Кнопки Grafana и сети
открывают фиксированные localhost-адреса в браузере. Grafana/monitor нужно заранее
поднять через `bin/sandbox up monitor`; пароль и секрет dashboard панель не читает.

Изменение токенов, логины, одобрение писем и применение infra-изменений остаются
в CLI первой версии. Тесты и проверки запускаются только по нажатию пользователя.
Приложение не меняет GitHub-защиту, не выполняет merge и не управляет хостовым VPN.

Renderer работает без Node integration, с context isolation, sandbox и CSP.
IPC доступен только основному локальному frame; системные операции выбираются
из фиксированного списка и запускаются без shell. Это граница GUI, а не замена
изоляции Docker или прав доступа хостового пользователя.

## Проверки

```sh
npm test
npm run check
npm run smoke       # графическая сессия, только деморежим
# На headless Linux:
xvfb-run -a npm run smoke
```

Smoke запускает настоящий Electron, проверяет preload/IPC, отсутствие Node API
в renderer, переходы к логам и ключам, остановку/запуск демоагента и узкое окно;
сохраняет `artifacts/demo.png` и `artifacts/demo-compact.png`.
Проверки controller используют синтетические данные и дочерние тестовые процессы;
контейнеры песочницы не запускаются и не останавливаются.

Правила Electron: [изоляция контекста](https://www.electronjs.org/docs/latest/tutorial/context-isolation)
и [безопасность IPC](https://www.electronjs.org/docs/latest/tutorial/security).
