# Работа агентов в этом репозитории

- До изменений проверь `git status`; сохраняй чужой WIP.
- Разработка ведётся в feature-ветках. Не коммить и не пушь напрямую в `main`.
- Представляй готовые изменения через PR в `main` для ревью пользователя.
  Не выполняй merge, auto-merge, административный обход и изменение защиты ветки.
- В общей рабочей копии не переключай ветку под работающим агентом. Назначай
  непересекающиеся write scopes; для независимых веток нужны отдельные каталоги.
- Для GUI актуальное состояние и интерфейс между частями: `docs/gui-state.md`.
  При работе через Herdr сначала читай `herdr --skill`, проверяй `HERDR_ENV=1`
  и обнаруживай реальные ID по проекту/cwd; не полагайся на унаследованные ID.
- Проверки GUI выполняй в деморежиме или с синтетическими данными. Не запускай,
  не останавливай контейнеры, не отправляй письма и не меняй хостовый VPN ради QA.
- Не читай и не публикуй значения из `secrets/`, `.env` и credential storage
  для реализации интерфейса. Достаточно метаданных о наличии ключей.

GitHub CLI сейчас использует аккаунт владельца. Для независимого обязательного
ревью PR агентам потребуется отдельная GitHub-учётная запись с ограниченными
правами: автор не может одобрить собственный PR. До этого PR служит местом
просмотра изменений пользователем; не утверждай, что изоляция прав обеспечена.
